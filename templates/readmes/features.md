# features — what this software does

<!-- managed by `novadev deploy`. -->

The registry of capabilities. One **folder** per feature,
`FEAT-NNNN-<kebab-slug>/`, holding:

| File | |
|---|---|
| `feature.md` | The document you write: frontmatter (`id`, `title`, `status`, `area`, `created`, `updated`, `tags`, `touches`, plus `depends-on` / `supersedes` / `superseded-by` / `conflicts-with`) then what it does, how it works, a progress log, open questions. |
| `work.md` | **Derived** — every todo, record, and commit that built it. |
| `tests.md` | **Derived** — the open human-test round, and every completed round in the archive with its verdict and evidence. |

Splitting the derived indexes out keeps `feature.md` readable once a capability has
accumulated twenty todos and eight test rounds.

The wiki says how the project is **built**; this says what it **has**. Its absence
is the signal that an agent must create it (`../skills/feature-init.md`).

**Search it before building anything new** — that is what it is for:

```sh
novadev features <query>            # name / area / tags / body
novadev features --touching src/x   # which features already own this code
novadev features --status planned
novadev features --new <slug>       # scaffold the next FEAT-NNNN
```

`INDEX.md`, `work.md`, and `tests.md` are **derived** — regenerated by
`novadev links --fix` from the `**Feature:**` / `**Commits:**` lines in todo records
and from the archived test rounds. Never hand-edit inside the
`<!-- novadev:*:begin/end -->` markers; anything outside them is preserved.

Playbooks: `../skills/feature-init.md` (create), `feature-check.md` (pre-flight a
proposal), `feature-update.md` (keep true after work lands), `links-audit.md`
(validate/repair the graph).
