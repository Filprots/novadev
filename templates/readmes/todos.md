# todos — task batches

<!-- managed by `novadev deploy`. -->

One batch = one folder `YYYY-MM-DD_N/` (`N` = same-day sequence, 1-based; `novadev
new` computes it). One todo = one folder inside the batch, optionally
order-prefixed (`01-…`); a `00-program` todo, when present, is the batch's owner
plan and is read first.

Inside a todo folder:
- **the brief** — human-authored `.txt`/`.md` files + optional screenshots; for a
  chat-initiated todo, the agent-transcribed `prompt.md`;
- **the record** — written by the agent when work concludes: `ai_completed.md`
  (implemented + verified) or `ai_failed.md` (deferred / cancelled / merged /
  blocked — which case and why), or `ai_progress.md` while long-running work is
  still in flight.

Todos are not only human-authored: when the human asks an agent in chat to
implement/fix/change something that no open todo covers, the agent must FILE it
here itself — transcribe the request as `prompt.md`, do the work, record the
outcome (plus its Thinking) — so chat-driven work is documented like any other.

For work you want done LATER rather than now, say so and let `/novadev-file-a-todo`
write the folder: your words go in verbatim, your screenshots are copied in beside
them, and nothing is written until you say yes to the split it proposes.

Record formats and all rules: `../skills/novadev-work.md`; `novadev sync` is what moves
finished work along.

**Finished batches stay here for a few days.** When every todo in a batch is
recorded, `novadev sync` writes an autogenerated `completed.md` at the batch root and
leaves the batch in place for `archiveGraceDays` (default 3, set in
`../novadev.json`) before moving it to `../archive/<year>/todos/`. So recent work is
still where you look for it, and the day's batch numbers stay visible — which is what
stops you from hand-creating a `_1` whose name the archive already took.

A batch carrying `completed.md` is **done, not pending**: agents will not re-run it or
add work to it. `novadev archive <batch>` archives one early if you want it gone.
